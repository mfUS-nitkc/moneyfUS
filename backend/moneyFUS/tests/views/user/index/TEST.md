# User テスト

## ユーザー 作成

### 成功シナリオ 1

想定しているAPIの使用方法

#### 前提

- 該当のemailを持つユーザーが存在しない。

#### 処理

- [ ] ユーザーをemail, username, passwordの必須フィールドを与えてPOSTする。

#### 結果

System
- [ ] ユーザーが正しく作成されている。

Response
- [ ] 201 Createdが返答される。
- [ ] ユーザーの情報が乗ったJSONオブジェクトがBodyで返答される。

### 成功シナリオ 2

余剰フィールド付与時

#### 前提

- 該当のemailを持つユーザーが存在しない。

#### 処理

- [ ] ユーザーをemail, username, password, その他余剰フィールドを与えてPOSTする。

#### 結果

System
- [ ] 余剰フィールドは記録されない。

Response
- [ ] 201 Createdが返答される。
- [ ] ユーザーの必須フィールドのデータのみが乗ったJSONオブジェクトがBodyで返答される。

### 成功シナリオ 3

必須フィールドのデータ型が期待したものと違う

#### 前提

- 該当のemailを持つユーザーが存在しない。

#### 処理

- [ ] ユーザーをemail, passwordをString型で，usernameフィールドをInteger型でPOSTする。

#### 結果

System
- [ ] Integer型をString型にキャストしてデータを保存している．

Response
- [ ] 201 Createdが返答される。
- [ ] ユーザーの必須フィールドのデータのみが乗ったJSONオブジェクトがBodyで返答される。
- [ ] usernameフィールドはString型にキャストされている．

### 失敗シナリオ 1

必須フィールドが不足している

#### 前提

- 該当のemailを持つユーザーが存在しない。

#### 処理

- [ ] ユーザーをemail, username, passwordのいずれかのフィールドが不足している状態でPOSTする。

#### 結果

System
- [ ] 内部的にユーザーは必須フィールドが与えられない状態で作成できない。

Response
- [ ] 400 Bad Requestが返答される。
- [ ] エラー原因(フィールド不足)が返答される。

### 失敗シナリオ 2

同じメールアドレスを持つユーザーが存在する．

#### 前提

- 該当のemailを持つユーザーが存在する．

#### 処理

- [ ] ユーザーをemail, username, passwordの必須フィールドを与えてPOSTする。

#### 結果

System
- [ ] 何も作成されていない．

Response
- [ ] 400 Bad Requestが返答される。
- [ ] エラー原因(すでにユーザーが作成されていること)が返答される。
